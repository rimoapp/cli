# 認証

[English](../en/authentication.md) | [日本語](../ja/authentication.md)

`rimo` は **OAuth 2.0 デバイス認可グラント** を使って Rimo Voice に認証します。
これは `gh auth login` と同じブラウザベースのフローです。トークンはプレーンテキスト
ファイルではなく、オペレーティングシステムの認証情報ストアによって安全に保存されます。

## ログイン

```bash
rimo auth login
```

1. `rimo` がワンタイムのユーザーコードと検証 URL を出力します。
2. Enter を押すとブラウザで URL が開きます（または手動で開きます）。
3. ブラウザでリクエストを承認します。
4. アクセストークンとリフレッシュトークンが OS の認証情報ストアに安全に保存されます。
   アカウントのエイリアスが `~/.config/rimo/config.yaml` に登録され、アクティブに
   設定されます。

## 複数アカウント

ログインに成功するたびに、メールアドレスと組織から導出されたアカウントのエイリアスが
作成されます（例: `alice-rimo-personal`）。複数のアカウントを同時に保持し、
切り替えることができます。

```bash
rimo auth status                  # 保存済みアカウントとトークン状態を一覧表示
rimo auth switch <alias|email|org>   # アクティブなアカウントを変更
rimo auth logout                  # アクティブなアカウントを削除（または --account を指定）
```

完全なフラグと解決ルールについては [コマンドリファレンス](commands.md#認証) を
参照してください。

## ヘッドレス / CI 認証

CI やその他の非対話環境では、`RIMO_TOKEN` 環境変数に API トークンを設定することで、
ブラウザフローをスキップできます:

```bash
export RIMO_TOKEN=your_api_token
rimo note list
```

設定されている場合、`RIMO_TOKEN` は `--account` や設定された既定アカウントよりも
優先されます。トークンはそのまま使われ、リフレッシュは行われません。

## トークン解決の優先順位

コマンドがトークンを必要とする場合、`rimo` は次の順序で解決します:

1. `RIMO_TOKEN` 環境変数（そのまま使用、リフレッシュなし）。
2. `--account <alias>` フラグ → 設定の検索 → 保存された認証情報。
3. 設定の `default_account` → 保存された認証情報。
4. いずれも解決できない場合、コマンドは認証エラー（終了コード 2）で終了し、
   *「Run `rimo auth login`」* というメッセージを表示します。

## 認証情報の保存場所

- **トークン** — OS の認証情報ストアに安全に保存されます（設定ファイルには保存されません）。
- **アカウントメタデータ**（エイリアス、メール、組織、既定アカウント） — `~/.config/rimo/config.yaml`。

ファイル形式については [設定](configuration.md) を参照してください。
